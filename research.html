Patent status and development

A U.S. provisional patent application filed in October 2026 describes the method behind RF-TraceGuard. This page covers the scope of the application, the parts already working in software and the work still ahead.

02 / Disclosed method

Main parts of the disclosed method

The application treats a test station as a set of physical routes through known components. Its main parts are summarized below in plain terms.

01

Overlapping routes

Controlled responses are taken through routes whose component sets are known and overlap by design. Components shared by the affected routes gain evidence, and components on unaffected routes lose it. The result is a single component, a group, a common-mode domain or an explicitly reported ambiguity.

02

Confirmed routes only

A route is set up by command, and its response enters the analysis once an independent indication confirms that the commanded configuration is the one actually in place. Otherwise the response counts as indeterminate and leaves every candidate in place.

03

Sensitivity before exclusion

A route that stayed normal clears a component only if a fault of the size in question in that component would have shown on it. Each exclusion records the fault size it covers.

04

Choosing the next route

Routes available under current conditions are scored by how well they would separate the remaining candidates. The chosen route is set up, verified and measured, and the process repeats until a stopping condition is met.

05

Ambiguity reported as such

Components with an identical signature across all available routes are reported together as one group. The route that would separate them is identified and, where possible, used.

06

Resolution known in advance

The route set of a station is characterized at configuration, so the attainable diagnostic resolution is known before any incident occurs.

The application also covers a validity assessment for each DUT measurement, with a guard band equal to the expanded uncertainty; separation of a product anomaly from a measurement-system anomaly by comparing DUT-dependent and DUT-independent responses; drift processing with a curvature check before a trend is extrapolated and with normalization for temperature; telling distributed degradation from a localized discontinuity by the shape of its frequency dependence; and advisory read-only operation in which the original result is kept.

03 / Software and method

The software today

The software used in the recorded applications corresponds to the reviewed software embodiment described in the application. It covers a defined part of the method, and the application itself keeps the disclosed method and the demonstrated program apart.

In the working software
  • Read-only operation on files the station already produces
  • A model of each station: components, paths, reference values and uncertainty contributions
  • Integrity class for each result: VALID, WARNING or REVIEW
  • Baseline, EWMA, linear trend and a forecast of the time to a threshold
  • Ranking of candidate components from affected paths, normal paths and reference deviations
  • Incident record with timeline, evidence and affected results
Disclosed, planned for the software
  • Setting up measurement routes by command
  • Confirming the established route before a response is used
  • The sensitivity condition for clearing a component
  • Ambiguity sets and the routes that separate them
  • Adaptive choice of the next route
  • A supervisory service for analysis across several stations

05 / Open work

Work ahead

01

Calibration on industrial data

The EWMA and trend thresholds and the weights of the diagnostic score will be refined on a larger body of industrial data. Until then the score serves to order candidates for inspection.

02

Station configuration

Station topology is currently defined in Python. Moving it to YAML or JSON files will let a new station be connected through configuration files alone.

03

Active components and VNA stations

An independent reviewer proposed extensions for test lines that include active components such as power amplifiers, and for stations built around a vector network analyzer with temperature taken into account.

04

Routes and fleets

Implementation of the route-based parts of the disclosed method, and analysis across several stations through a shared topology and baseline repository.

Supporting documents, including the technical description (version 4.6, 5 July 2026), the prior-art landscape and statement of novelty, and the originality summary, are available to qualified reviewers on request.
